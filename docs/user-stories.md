# User Stories — قصص المستخدم
## Smart Hospitals — نظام إدارة مستشفى الشفاء

**الفريق:** معتز بشير محمد مصلح، صقر نبيل قاسم أحمد، محمد سيف عبده مسعد قايد، أنس محمد أمين طه الإدريسي
**المقرر:** البرمجيات (عملي) — د. ساهر الهمداني
**التاريخ:** 2026-09-27

---

## مقدمة

قصة المستخدم هي وصف مختصر للمطلوب من وجهة نظر المستخدم المستفيد.
**الصيغة:** بصفتي [نوع المستخدم]، أريد [الوظيفة]، حتى [الفائدة].

**هذا الملف يفصّل قصص المستخدم لمشروع Smart Hospitals، مرتّبة حسب الدور.**

---

## 1. قصص دور المدير (Admin)

### US-A01: إدارة المستخدمين
**بصفتي** مدير المستشفى، **أريد** إضافة مستخدم جديد (طبيب، صيدلي، استقبال)، **حتى** أتمكن من توسيع فريق العمل.

**معايير القبول (Given-When-Then):**
- **Given** أنا مسجل دخول كمدير
- **When** أفتح صفحة `New User` وأملأ البيانات
- **Then** يُنشأ المستخدم بدور محدد

**حالات الحافة:**
- بريد مكرر → رفض + رسالة
- كلمة مرور أقل من 8 → رفض

**مرتبطة بـ:** — (إدارة نظام، خارج FRs الثمانية)

---

### US-A02: إعادة ضبط كلمة المرور
**بصفتي** مدير المستشفى، **أريد** إعادة ضبط كلمة مرور أي موظف، **حتى** يستعيد الدخول عند نسيانها.

**معايير القبول:**
- **Given** أنا في صفحة `Reset User`
- **When** أختار المستخدم وأؤكد بكلمة مروري
- **Then** تُعاد الكلمة إلى الافتراضية `12345678` مع رسالة تأكيد

**حالات الحافة:**
- كلمة المدير غير صحيحة → رفض العملية
- مستخدم غير موجود → رسالة خطأ

**مرتبطة بـ:** — (إدارة نظام)

---

### US-A03: عرض الإحصائيات
**بصفتي** مدير المستشفى، **أريد** لوحة إحصائيات برسوم بيانية، **حتى** أتابع نشاط المستشفى شهرياً.

**معايير القبول:**
- **Given** أنا مسجل دخول كمدير
- **When** أفتح `/stats`
- **Then** أرى مرضى الشهر (خارجي/رقود/جدد)، Top أدوية، ورسوم Chart.js بسنوات ديناميكية

**حالات الحافة:**
- سنة بلا بيانات → رسوم فارغة بلا خطأ

**مرتبطة بـ:** FR-08

---

### US-A04: إصدار التقارير
**بصفتي** مدير المستشفى، **أريد** إصدار 4 تقارير PDF بالعربية، **حتى** أوثق العمل وأرفعه للجهات.

**معايير القبول:**
- **Given** أنا مسجل دخول كمدير
- **When** أختار نوع التقرير والفترة وأضغط توليد
- **Then** يُنزَّل PDF عربي (DejaVu) بترويسة المستشفى

**حالات الحافة:**
- فترة بلا بيانات → جدول فارغ + رسالة
- فاتورة محذوفة → تحويل + رسالة بدل 404

**مرتبطة بـ:** FR-08

---

### US-A05: عرض الفواتير الشهرية
**بصفتي** مدير المستشفى، **أريد** تقرير الفواتير الشهري، **حتى** أعرف الإيرادات والمتبقي.

**معايير القبول:**
- **Given** أنا في `/invoices/report/monthly`
- **When** أختار السنة والشهر
- **Then** أرى 4 صناديق (عدد/إجمالي/مدفوع/متبقي) + جدول الفواتير

**حالات الحافة:**
- شهر بلا فواتير → أصفار + جدول فارغ

**مرتبطة بـ:** FR-06

## 2. قصص دور الطبيب (Doctor)

### US-D01: فحص مريض
**بصفتي** طبيب، **أريد** فحص مريض وكتابة وصفة طبية، **حتى** أقدم العلاج المناسب.

**معايير القبول:**
- **Given** أنا في صفحة `Check Patient`
- **When** أدخل رقم الموعد + التشخيص + القياسات + الأدوية
- **Then** تُحفظ الوصفة ويُحدَّث الموعد `completed=YES`
- **And** يُنشأ **فاتورة كشف تلقائية** (5000 YER)

**حالات الحافة:**
- موعد غير موجود → رسالة "غير موجود"
- وصفة بدون أدوية (مسموح — تشخيص فقط)
- فشل حفظ → rollback + سجل خطأ

**مرتبطة بـ:** FR-03

---

### US-D02: طلب رقود مريض
**بصفتي** طبيب، **أريد** تحويل مريض إلى منوّم في جناح، **حتى** يتلقى رعاية مستمرة.

**معايير القبول:**
- **Given** المريض مفحوص وله موعد
- **When** أضغط تحويل رقود وأختار الجناح
- **Then** يُنشأ سجل `inpatients` وتنقص الأسرّة الحرة + فاتورة رقود

**حالات الحافة:**
- لا أسرّة حرة → منع + رسالة
- مريض منوّم أصلاً → تنبيه تكرار

**مرتبطة بـ:** FR-01

---

### US-D03: عرض ملف المريض
**بصفتي** طبيب، **أريد** فتح ملف أي مريض، **حتى** أرى بياناته وحالته قبل الفحص.

**معايير القبول:**
- **Given** أنا في البحث
- **When** أضغط على مريض
- **Then** أرى البيانات + الحالة (نشط/غير نشط) + آخر زيارة + عدد الزيارات

**حالات الحافة:**
- مريض محذوف ناعماً → يُعرض كغير نشط مع إمكانية الاستعادة

**مرتبطة بـ:** — (عرض ملف)

---

### US-D04: عرض التاريخ العلاجي
**بصفتي** طبيب، **أريد** رؤية وصفات المريض السابقة مرتبة زمنياً، **حتى** أتجنب تعارض الأدوية.

**معايير القبول:**
- **Given** أنا في ملف المريض
- **When** أفتح التاريخ العلاجي
- **Then** أرى كل الوصفات (تشخيص + أدوية + طبيب + تاريخ) من الأحدث

**حالات الحافة:**
- مريض بلا وصفات → رسالة "لا تاريخ علاجي"

**مرتبطة بـ:** — (عرض ملف)

---

### US-D05: خروج منوّم
**بصفتي** طبيب، **أريد** تخريج مريض منوّم عند تحسنه، **حتى** تُحرَّر سريره وتُحسب مدة الرقود.

**معايير القبول:**
- **Given** أنا في صفحة الخروج
- **When** أدخل رقم المريض وأؤكد الخروج
- **Then** يُعلَّم `discharged=YES` + يزيد السرير الحر + تُحدَّث فاتورة الرقود بالأيام الفعلية

**حالات الحافة:**
- مريض غير منوّم → رسالة خطأ
- رقود يوم واحد → يُحسب يوماً واحداً (min يوم)

**مرتبطة بـ:** FR-06 (تسوية الفاتورة)

## 3. قصص دور الصيدلي (Pharmacist)

### US-P01: صرف دواء
**بصفتي** صيدلي، **أريد** صرف دواء من الوصفة، **حتى** يستلم المريض دواءه.

**معايير القبول:**
- **Given** أنا في صفحة `Issue Medicine`
- **When** أدخل رقم الموعد وأضغط "Issue" لكل دواء
- **Then** يُخصم من المخزون (FEFO)
- **And** يُنشأ **فاتورة دواء تلقائية**

**حالات الحافة:**
- دواء نافد → رفض + "نفد المخزون"
- دواء منتهي الصلاحية → رفض + "كل الدفعات منتهية"

**مرتبطة بـ:** FR-04

---

### US-P02: عرض المخزون
**بصفتي** صيدلي، **أريد** صفحة مخزون بالدفعات، **حتى** أعرف الرصيد وتواريخ الانتهاء.

**معايير القبول:**
- **Given** أنا في `/medicine-stocks`
- **When** تفتح الصفحة
- **Then** أرى كل دواء + دفعاته (كمية/انتهاء) + شارات OK/LOW/OUT

**حالات الحافة:**
- دواء بلا دفعات → صف OUT

**مرتبطة بـ:** FR-05

---

### US-P03: تنبيهات المخزون
**بصفتي** صيدلي، **أريد** 3 تنبيهات علوية، **حتى** أتصرف قبل الأزمة.

**معايير القبول:**
- **Given** أنا في صفحة المخزون
- **When** تفتح الصفحة
- **Then** أرى عدّادات: نافد (أحمر) + منخفض <10 (أصفر) + ينتهي خلال 30 يوماً (سماوي)

**حالات الحافة:**
- مخزون سليم كاملاً → أصفار خضراء

**مرتبطة بـ:** FR-05

---

## 4. قصص دور الاستقبال (General)

### US-G01: تسجيل مريض جديد
**بصفتي** موظف استقبال، **أريد** تسجيل مريض جديد، **حتى** يحصل على رقم وبطاقة.

**معايير القبول:**
- **Given** أنا في `Register New`
- **When** أملأ البيانات + صورة الكاميرا
- **Then** يُنشأ برقم `YYMMDD+seq` + بطاقة باركود

**حالات الحافة:**
- NIC مكرر → تنبيه (الحقل اختياري أصلاً)
- صورة مفقودة → صورة افتراضية

**مرتبطة بـ:** FR-01

---

### US-G02: حجز موعد
**بصفتي** موظف استقبال، **أريد** حجز موعد اليوم، **حتى** يدخل المريض دور الفحص.

**معايير القبول:**
- **Given** أنا في `Create Appointment`
- **When** أدخل رقم التسجيل + وقت الجدولة
- **Then** رقم تسلسلي + فاتورة حجز (1000 YER) + رابط طباعة فوري

**حالات الحافة:**
- رقم تسجيل خاطئ → "رقم غير صالح"
- انقطاع النت → "خطأ في الاتصال"

**مرتبطة بـ:** FR-02

---

### US-G03: إصدار بطاقة مريض
**بصفتي** موظف استقبال، **أريد** طباعة بطاقة المريض، **حتى** يستخدمها في كل زيارة.

**معايير القبول:**
- **Given** المريض مسجل
- **When** أفتح بطاقته
- **Then** بطاقة بصورة + باركود Code39 برقم التسجيل

**حالات الحافة:**
- مريض بلا صورة → صورة افتراضية

**مرتبطة بـ:** FR-01

---

### US-G04: إنشاء فاتورة + دفع
**بصفتي** موظف استقبال، **أريد** إنشاء فاتورة يدوية وتسجيل دفعة، **حتى** أُحاسب المريض.

**معايير القبول:**
- **Given** أنا في `New Invoice`
- **When** أختار المريض + البنود + المبلغ
- **Then** فاتورة `unpaid` → بعد الدفع `partial/paid` + إيصال PDF

**حالات الحافة:**
- مبلغ سالب → رفض (validation)
- مبلغ أكبر من الإجمالي → منع + تنبيه

**مرتبطة بـ:** FR-06

---

### US-G05: البحث عن مريض
**بصفتي** موظف استقبال، **أريد** البحث بالاسم/الوطني/الهاتف، **حتى** أجد المريض بسرعة.

**معايير القبول:**
- **Given** أنا في `Search Patient`
- **When** أدخل كلمة + فئة البحث
- **Then** نتائج فورية (LIKE) تشمل المحذوفين ناعماً بتمييز

**حالات الحافة:**
- لا نتائج → رسالة فارغة واضحة

**مرتبطة بـ:** FR-01
