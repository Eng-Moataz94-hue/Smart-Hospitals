# Acceptance Criteria — معايير القبول
## Smart Hospitals — نظام إدارة مستشفى الشفاء

**الفريق:** معتز بشير محمد مصلح، صقر نبيل قاسم أحمد، محمد سيف عبده مسعد قايد، أنس محمد أمين طه الإدريسي
**المقرر:** البرمجيات (عملي) — د. ساهر الهمداني
**التاريخ:** 2026-09-27

---

## مقدمة

معايير القبول تحدد **متى تكون القصة مكتملة**.
**الصيغة:** Given (الوضع) - When (الحدث) - Then (النتيجة).

**الهدف:** كل متطلب قابل للاختبار.

---

## 1. معايير قبول FR-01 (تسجيل مريض)

### AC-1.1: تسجيل ناجح
- **Given** أنا موظف استقبال مسجل دخول
- **When** أملأ: name، address، sex، bod، telephone، occupation
- **Then** يُنشأ المريض برقم `YYMMDD+seq` ويظهر في القائمة

### AC-1.2: فشل بدون الاسم
- **Given** أنا في صفحة التسجيل
- **When** أترك `name` فارغاً وأضغط حفظ
- **Then** يظهر خطأ "الاسم مطلوب"

### AC-1.3: بطاقة الباركود
- **Given** مريض مسجل
- **When** أفتح `/patientregcard/{id}`
- **Then** تظهر بطاقة بباركود + صورة

### AC-1.4: حفظ الصورة
- **Given** أنا أرفع صورة
- **When** أحفظ
- **Then** تُحفظ في `storage/app/public/{id}.png`

## 2. معايير قبول FR-02 (حجز موعد)

### AC-2.1: حجز ناجح + فاتورة تلقائية
- **Given** أنا في `Create Appointment`
- **When** أدخل رقم تسجيل مريض + وقت الجدولة
- **Then** يُنشأ موعد + **فاتورة حجز تلقائية 1000 YER**

### AC-2.2: رقم تسلسلي يومي
- **Given** عدة حجوزات في نفس اليوم
- **When** يُحجز كل موعد
- **Then** `number` يتسلسل 1، 2، 3... (يُصفَّر كل يوم جديد)

### AC-2.3: وقت الجدولة (`scheduled_at`)
- **Given** أنا أحجز موعداً
- **When** أختار وقتاً من حقل datetime
- **Then** يُحفظ في `scheduled_at` (ويُستخدم `now()` عند الترك فارغاً)

---

## 3. معايير قبول FR-03 (فحص طبي)

### AC-3.1: حفظ وصفة كاملة
- **Given** أنا طبيب في `Check Patient`
- **When** أدخل التشخيص + القياسات + قائمة أدوية
- **Then** تُحفظ `Prescription` + سطور `medicine_prescription` بملاحظاتها

### AC-3.2: موعد → `completed=YES`
- **Given** وصفة حُفظت لموعد
- **When** يكتمل الحفظ
- **Then** `appointments.completed='YES'` و`doctor_id` = الطبيب الفاحص

### AC-3.3: فاتورة كشف 5000 YER تلقائية
- **Given** فحص مكتمل
- **When** يُحفظ الفحص
- **Then** فاتورة `consultation` مستقلة بقيمة 5000 YER

### AC-3.4: القياسات بصيغة JSON
- **Given** فحص بضغط/سكر/كولسترول
- **When** تُحفظ الوصفة
- **Then** كل قياس `{value, updated}` ويُعرض السابق للطبيب في الزيارة التالية

## 4. معايير قبول FR-04 (صرف دواء FEFO)

### AC-4.1: صرف ناجح + خصم من المخزون
- **Given** وصفة اليوم معروضة في `show.blade.php`
- **When** أضغط "Issue" على دواء
- **Then** `issued='YES'` + خصم وحدة من الدفعة + عدّاد `qty` يزيد

### AC-4.2: رفض عند النفاد → code 400
- **Given** رصيد الدواء صفر
- **When** أضغط "Issue"
- **Then** JSON `{code: 400, reason: 'OUT_OF_STOCK'}` + تنبيه "نفد المخزون" + `issued` تبقى `NO`

### AC-4.3: ترتيب FEFO (الأقرب انتهاءً أولاً)
- **Given** دفعتان (تنتهي في 6 أشهر و12 شهراً)
- **When** يُصرف دواء
- **Then** يُخصم من دفعة الـ 6 أشهر أولاً (`ISNULL(expiry_date), expiry_date ASC`)

### AC-4.4: منع الصرف المتزامن (lockForUpdate)
- **Given** صيدليان يصرفان آخر وحدة معاً
- **When** يصل الطلبان معاً
- **Then** واحد ينجح والثاني يتلقى `OUT_OF_STOCK` (لا رصيد سالب أبداً)

## 5. معايير قبول FR-05 (مخزون)

### AC-5.1: صفحة `/medicine-stocks` تعرض 3 تنبيهات
- **Given** أنا صيدلي/مدير
- **When** أفتح الصفحة
- **Then** 3 صناديق: نافد (أحمر) + منخفض <10 (أصفر) + ينتهي ≤30 يوماً (سماوي)

### AC-5.2: تصنيف (نافد / منخفض / قارب الانتهاء)
- **Given** جدول الدفعات
- **When** يُعرض كل سطر
- **Then** شارة `OUT/LOW/OK` + شارة حمراء للدفعة المنتهية أو القريبة

---

## 6. معايير قبول FR-06 (فواتير)

### AC-6.1: فاتورة مستقلة لكل عملية
- **Given** مريض بحجز + كشف + دواء في نفس اليوم
- **When** تتم العمليات الثلاث
- **Then** 3 فواتير بأنواع `appointment/consultation/medicine` (لا دمج)

### AC-6.2: 4 أنواع (appointment/consultation/medicine/ward)
- **Given** كل عملية طبية
- **When** تُنفَّذ
- **Then** نوع الفاتورة يطابق العملية + شارة ملونة في القائمة

### AC-6.3: دفع جزئي → `partial`
- **Given** فاتورة 5000
- **When** أدفع 2000
- **Then** `paid_amount=2000` والحالة `partial` (مُثبت باختبار آلي)

### AC-6.4: دفع كامل → `paid`
- **Given** فاتورة بمتبقي
- **When** أضغط "Mark as Paid" أو أدفع الباقي
- **Then** الحالة `paid` (مُثبت باختبار آلي)

### AC-6.5: دفع زائد → رفض
- **Given** فاتورة بمتبقي 1000
- **When** أحاول دفع 5000 يدوياً
- **Then** منع + تنبيه (زر "Mark as Paid" يدفع الباقي فقط)

### AC-6.6: تصدير PDF
- **Given** فاتورة موجودة
- **When** أفتح `/invoices/{id}/pdf`
- **Then** `200 + application/pdf` عربي كامل (مُثبت باختبار آلي)

## 7. معايير قبول FR-07 (حضور)

### AC-7.1: تسجيل دخول (`GET /attendance?finger=&time=`)
- **Given** بصمة مسجلة لموظف
- **When** يرسل الجهاز finger + time
- **Then** سجل جديد بحقل `start` + JSON `{status:200}`

### AC-7.2: تسجيل خروج (يُغلق السجل المفتوح)
- **Given** سجل اليوم بلا `end`
- **When** إرسال ثانٍ بنفس اليوم
- **Then** يُملأ `end` بدل إنشاء سجل جديد

### AC-7.3: حساب المدة تلقائياً
- **Given** سجلات start/end
- **When** عرض "حضوري"
- **Then** المدة بالساعات + تقويم + عدّ الأيام الكاملة (>7h) والناقصة (<5h)

## 8. معايير قبول FR-08 (تقارير)

### AC-8.1: 4 تقارير PDF
- **Given** أنا مدير
- **When** أطلب عيادة/حضور/منوّمين/شهري
- **Then** PDF يُنزَّل لكل نوع (مُولَّدة ومُختبرة: ~878KB)

### AC-8.2: عربية RTL كاملة
- **Given** أي تقرير
- **When** يُفتح
- **Then** `dir="rtl"` + DejaVu Sans (لا مربعات)

### AC-8.3: فترة زمنية قابلة للتخصيص
- **Given** صفحة التقرير
- **When** أحدد من/إلى (أو سنة/شهر)
- **Then** البيانات تُفلتر على الفترة (bindings آمنة)

## 9. معايير قبول NFR

### NFR-01 (الأداء): كل صفحة < 2 ثانية
- **Given** ظروف طبيعية
- **When** أفتح أي صفحة
- **Then** استجابة كاملة خلال ثانيتين (السويت كله يعمل بهامش مشابه)

### NFR-02 (الأمان): bcrypt + CSRF + RBAC
- **Given** أي طلب
- **When** يُنفَّذ
- **Then** كلمات bcrypt + CSRF على النماذج + middleware أدوار + bindings (مُثبت باختبارات 302)

### NFR-03 (UX): RTL + متجاوب
- **Given** التحويل للعربية
- **When** تفتح أي صفحة
- **Then** `dir="rtl"` + `rtl.css` + تخطيط معكوس سليم (مُختبر حياً)

### NFR-04 (الموثوقية): activity_log + SoftDeletes
- **Given** أي عملية حرجة
- **When** تتم
- **Then** سجل `activity()` + حذف ناعم قابل للاسترجاع

### NFR-05 (الصيانة): MVC + 27 اختبار
- **Given** تعديل مستقبلي
- **When** يُنفَّذ
- **Then** السويت (27/43) يكشف الانحدار على قاعدة معزولة
